RULE-BASED SIEM BASELINE (CICIDS-2017, unified test split)
======================================================================
Command: python -m src.evaluation.siem_baseline

======================================================================
1. SCOPE
======================================================================
Test rows: 504,193 (85,148 attack, 419,045 BENIGN).
Each rule is one row of RULES in src/evaluation/siem_baseline.py. The SIEM alerts when any
implementable rule fires. Rules and percentiles were fixed before any test number was seen
and were not tuned afterwards.

======================================================================
2. THRESHOLD DERIVATION
======================================================================
Features in the parquet are MinMax-scaled to the train split, so raw packet-count thresholds are
meaningless. Every threshold is a percentile of that column over BENIGN rows of
cicids2017_unified_train.parquet, computed by derive_thresholds(train). Nothing is
read from the test split except to score it. Percentiles are a-priori analyst choices (p99 for
abnormally high, p25 for abnormally low rate), not searched.

R1 Port scan [T1046 Network Service Discovery]
    uniq_dport_count_1m >= 0.556585 (train-BENIGN p99) AND conn_count_1m >= 0.015010 (train-BENIGN p95)
R2 Brute force (repeated same-port logins) [T1110.001 Brute Force: Password Guessing]
    repeat_ratio_5m >= 0.007852 (train-BENIGN p99) AND conn_count_5m >= 0.011495 (train-BENIGN p90)
R3 Connection flood [T1498 Network Denial of Service]
    conn_count_1m >= 0.040612 (train-BENIGN p99)
R4 Slow-rate DoS [T1499.002 Endpoint DoS: Service Exhaustion Flood]
    Flow Duration >= 0.984006 (train-BENIGN p99) AND Flow Packets/s <= 0.333335 (train-BENIGN p25)
R5 Repeated-target beaconing [T1071.001 Application Layer Protocol: Web Protocols]
    repeat_ratio_5m >= 0.007852 (train-BENIGN p99) AND conn_count_5m <= 0.003155 (train-BENIGN p50)

======================================================================
8. CAVEATS
======================================================================
Window features are computed per source IP over the whole capture, so BENIGN heavy talkers
(servers, scanners-by-design) trip volume rules; this is the realistic cost of static rules.
The test set carries natural class prevalence, so precision depends on it; recall and FPR do not.
